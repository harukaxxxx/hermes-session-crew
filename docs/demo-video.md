# SessionCrew 展示影片企劃

## 狀態與範圍

- 本文件記錄已由使用者定案的創意方向與製作邊界，是後續分鏡、錄影與 Remotion 製作的依據。
- 目前階段：已有 64 秒審閱剪輯、原生操作素材與 8 秒 v4 片尾；新標題劇情正在補拍，同一 Webapp 內的插件狀態展示尚未完成。影片尚未驗收。
- 交付目標：少於 90 秒、展示插件實際運作的產品影片。工作時間軸以 86 秒為目標，依真實操作素材調整，不以壓縮閱讀時間強塞內容。
- 本文件不是 live 驗收、參賽資格或官方規則已查核的證明；正式投稿前依 AGENTS.md 重查最新規則。
- 不因本企劃修改產品 README、宿主 UI、Hermes core 或 SDK。建立 profiles、啟用服務、模型工作、安裝依賴及發布等執行事項，留待製作階段確認相應授權。

## 核心方向

### 最新製作決議（優先於下方早期真實工作分鏡）

- 使用者已允許預寫英文劇情與合成狀態展示；匯入對話不等於啟動 turn，也不能用來證明模型、完成事件或子代理確實執行。
- 使用者另已批准在 demo worktree 與 `/Users/haruka/SessionCrew-Demo` 製作、套用及錄製插件自有的 opt-in 狀態 adapter，包括公開重載與必要的隔離 gateway 重啟。這不是正式環境的部署授權。
- adapter 預設關閉，合成來源與原生執行資料分離；不得改 core／SDK、宿主 DOM／CSS、原生資料庫或執行紀錄。部署、已登入端點讀回及同一 Webapp 的可見狀態切換分別驗收。
- 使用者最新明確要求：**畫面不要顯示 scripted demo 或同類免責浮水印**。移除插件拍攝介面與影片上的這類文案；來源資訊保留於內部 metadata 與製作紀錄，不改稱真實模型執行。
- 獨立 `video/feature-demo` 素材只是受控 renderer 展示，不能代替同一 Webapp 內的插件動態驗收；片中不得把它剪成原生工作紀錄。
- 全片保留亮色、完整可讀選單與泡泡，以 motion design 引導而非逐句字幕；Odin 台詞與品牌標語維持定稿。
- 故事不採獨立台詞卡或助手單向摘要。Webapp 保留為畫面主體，右側自然漸層淡出，以文字動態完整呈現使用者發話與 Agent 回覆；不可為了隱藏舊前綴只留下窄頭像列。
- 必須保留操作因果：Heimdall 舉手 → 點開泡泡 → 點對應 session 讀取；Loki 快速新增 session；Odin 從入口實際進入 Ragnarök。只展示提醒靜幀或選單不等於完成這些動作。
- 使用者已明確刪除片尾前的拉線合流概念頁（`GodsConverge`）：改為鏡頭掃過醒來工作的 Thor、Tyr、Freyja、Frigg，再切近 Odin 呈現來源中的子代理疊影展開，最後銜接品牌片尾；不換成另一張線圖或任務文字卡。

- 展示插件已依使用者授權更新至本機 main `40bc67c`，經公開 Rescan／Reload 流程並重啟隔離 gateway；Ego 中可見亮色側欄，status 與 completion-snapshot 回傳 HTTP 200。這不代表模型工作已可執行或所有拍攝互動已驗收。

- 取景原則：全景只用來交代空間與高潮回拉；主要操作以頭像列、選單與對話結果的中近景銜接。保留足夠空間讓選單完整展開，不靠全片固定全螢幕或捏造 UI 重排來展示功能。

**產品紀錄片為主，加入動畫概念片的轉場與高潮。**

故事以北歐神祇追趕 `Ragnarök`（諸神黃昏）專案進度為線索，讓觀眾自然看見完成提醒、跨 profile 導航、快速新增 session、專案入口、狀態與子代理疊影，而不是逐項朗讀功能清單。

敘事順序：

> 密集 session 清單 → 原生面板收合與頭像同步展開 → 忙碌與沉睡並存 → 舉手提醒 → 跨 profile 接力 → 追到 Ragnarök → 諸神醒來 → Odin 展開子代理工作 → 主視覺拼合。

笑點：連世界末日都需要有人追進度；Odin 用合體機器人隊長的語氣號令大家，而 Baldr 始終離線。

## 角色與真實工作安排

以八位神作為目前構圖基準。主角三位，前半段離線五位；高潮時四位離線 profile 醒來，只有 Baldr 保持離線。

| Profile | 前半段安排 | 高潮安排 | 敘事責任 |
|---|---|---|---|
| Heimdall | 真實工作完成後出現 ✋ | 保持在線 | 完成監看，點名 Loki |
| Loki | 等待／可回應 | 回覆追問 | 引導至 Ragnarök 與 Odin |
| Odin | 在線／可工作 | 自己派出七個子代理 | 專案負責人、高潮主角 |
| Thor | 離線 | 真實開始工作 | 第一位響應 |
| Tyr | 離線 | 真實開始工作 | 第二位響應 |
| Freyja | 離線 | 真實開始工作 | 第三位響應 |
| Frigg | 離線 | 真實開始工作 | 第四位響應 |
| Baldr | 離線 | 始終離線 | 不解釋的背景彩蛋 |

**早期分鏡的規模：四個 profile 響應，加上 Odin 的七路子任務意象。** 最新授權允許以隔離 adapter 控制展示狀態；四個 profile 不冒充 Odin 的子代理，合成狀態不作為真實執行證據，疊影遵守產品實際呈現規則。

使用者允許依畫面密度減少 profile 與相應離線數量；但目前先保留上述八位與四位醒來的版本。若製作時需要縮編，明確更新本文件，不默默改變這項工作安排。

展示 Webapp 已有拍攝用 profiles，沿用既有環境，不另行建立。`/Users/haruka/SessionCrew-Demo/profile-map.json` 記錄神祇角色映射，其中 Odin 對應 `default`。模型工作內容、啟動安排與錄製就緒狀態仍待確認；既有合成 sessions 不等於已執行本片所需工作。

## 時間軸與分鏡

以下為剪輯工作目標，不是已錄製或驗證的片長。

| 時間 | 實際畫面／操作 | 動畫與敘事重點 |
|---|---|---|
| 0–7 秒 | 原生 session 面板顯示全部 profiles 混合的大量 sessions，掃過清單與 profile 標記 | 呈現真實資訊密度，不醜化原生介面；暫擬短句「Many profiles. Even more sessions.」 |
| 7–15 秒 | 收合原生 session 面板，同時引入 SessionCrew | 頭像隨 panel 展開方向接力噴出，帶短促拖影，落定為真實介面 |
| 15–21 秒 | 展示收合後的對話空間與 SessionCrew 全貌 | 讓觀眾理解新的導航入口；暫擬短句「Your crew. Within reach.」 |
| 21–29 秒 | 多個 profile 的不同真實狀態同時存在，五位維持離線 | 一整排忙碌感；焦點最後停在 Heimdall 的 ✋ |
| 29–40 秒 | 點 Heimdall 頭像，開啟舉手對應的已完成 session | 對話提到 Loki，交代提醒、導航與結果的因果 |
| 40–52 秒 | 點 Loki 頭像，快速新增 session，告知 Heimdall 在找他並收到回覆 | Loki 提到 Ragnarök，形成跨 profile 接力 |
| 52–65 秒 | 點 Odin 頭像，從專案入口選擇事先建立的 Ragnarök，在該專案對話中催進度 | 專案名稱與建立／開啟對話的結果要可讀；依實際產品操作確認精確路徑 |
| 65–78 秒 | Odin 說出定案台詞；四個真實 profile 醒來工作，Odin 自己派出七個子代理 | 狀態逐步忙起來，鏡頭聚焦 Odin 的真實疊影，回拉時 Baldr 仍離線；不在台詞強調七路 |
| 78–86 秒 | 頭像、氣泡與線條轉入動畫，拼成新版 README 主視覺 | 主視覺完成後顯示 SessionCrew 與「Interact with sessions like bots.」，留定格閱讀時間 |

如真實操作需要較多閱讀時間，優先縮短裝飾段落與非必要字幕，不把所有操作加速到難以辨認。最終輸出必須實測少於 90 秒。

## 對話腳本

### 定案台詞：Odin

> 那就喚醒諸神。我來組成頭部！

不替換成「七路並進」，不額外口述七個子代理。台詞先讓觀眾讀到笑點，再接工作與疊影高潮。

### 銜接台詞：工作稿，保留角色與資訊意圖

以下尚可依錄製語言、閱讀時間與人設微調，並非全部逐字鎖定。

**Heimdall：**

> 九界的進度查完了。大家都準備好了——除了 Loki。有人能問問他，彩虹橋的驗收報告在哪裡嗎？

**新增 Loki session 後的訊息：**

> Heimdall 在找你。彩虹橋的驗收報告呢？

**Loki：**

> 肯定又是 Ragnarök。他們把世界末日排上日程，卻忘了找 Odin 核准。

**給 Odin 的催進度訊息：**

> 眾神還在等你的號令。再拖下去，諸神黃昏就只剩黃昏了。

銜接對話須避免與畫面矛盾：「大家準備好了」可以指準備工作完成，不表示五位離線 profile 已上線。全片讓觀眾能讀懂訊息，不以大量長回覆填滿畫面。

## 動畫設計

### 同步收合與頭像噴出

- 原生面板收合與頭像展開放在同一拍，不保留舊版先開 SessionCrew、再另行關閉清單的順序。
- 優先使用真實收合動作，讓頭像的方向性動勢承接騰出的空間。
- 原生收合目前沒有動畫；不為此新增宿主動畫。如果剪接突兀，可用收合前後錄影片段在 Remotion 中做短暫水平收束。
- 後製過渡完成後落回真實操作畫面。不得把原生清單變形成匯入結果，暗示插件搬移了 sessions。
- 不操作或改寫宿主 DOM／CSS，不修改 core／SDK。

### 諸神醒來與 Odin 疊影

- 四個 profile 的狀態變化與 Odin 疊影可使用已授權、獨立於原生執行資料的隔離 adapter；若採合成來源，內部紀錄須保留，不宣稱是真實工作。
- Odin 台詞 → 四位響應 → Odin 派工／疊影 → 回拉全貌，形成遞進；實際啟動時間可依錄製條件安排，剪輯保留因果，不捏造運作能力。
- 概念動畫可用短促分流、光跡或任務標籤強調忙碌，但不畫出不存在的 UI 狀態。
- 不強行顯示七層疊影；保留產品實際裁切與呈現規則，不將活動徽章解讀為子代理數量。
- Baldr 保持離線，不額外加解釋字幕或旁白。

### 主視覺拼合

- 使用新版 README 的 `assets/sessioncrew-hero.png` 作為最後視覺落點。
- 頭像、氣泡與連線先作為轉場語彙，再轉化成插畫碎片或構圖元素，拼合完整主視覺。
- 以暖白留白包住原色插畫，墨綠文案、少量橙紅點綴呼應既有識別；不反相原圖，不以深色滿版或泛用科技粒子取代。
- 最後主視覺先完成，結尾標語再落下，保留可讀的定格。

## 製作方式與技能分工

- `remotion`：可編輯影片專案、素材與場景組織。
- `remotion-best-practices`：依影格驅動、媒體處理、Studio 預覽與可靠輸出；實作時載入相應專項 reference。
- `motion-design`：沉穩俐落的動態語彙、注意力引導與高潮節奏。
- `stageshow`：借用取景、局部特寫與操作因果方法，不用仿製 UI 取代實際功能證據。
- Remotion 負責剪輯、裁切推近、字幕、轉場與品牌動畫；真實錄影負責證明產品功能。

建議製作預設（尚非全部定案）：16:9、1920×1080、30 fps；英文投稿版，先以繁中確認角色對話，再確認英文版本與是否配旁白。Odin 定案笑點的英文改寫須另行審閱，不靜默換成不同台詞。音樂低干擾，少量操作與完成提示音，不為每次移動加音效。
